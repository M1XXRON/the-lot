Дом драфта на двоих: пять пиков, двадцать монет, один победитель. Сервер на Bun, состояние на сервере, UI обновляется HTML-патчами по SSE через Datastar.

**Прод:** <https://lot.bunker9.lol> · **Код:** <https://github.com/M1XXRON/the-lot> · **Лицензия:** MIT

## Стек

| Слой | Что |
| --- | --- |
| Рантайм | Bun 1.4 (`Bun.serve`, `bun:sqlite`, `bun build --compile`) |
| Транспорт | SSE `/stream` + `POST /act/:cmd`, патчи `datastar-patch-elements` |
| Клиент | Datastar 1.0.5 (вендор), `public/experience.js`, `public/sound.js` |
| Стили | `public/style.css` (токены, база), `redesign.css` (лендинг, каталог), `stages.css` (торги) |
| Данные | `packs.json` (222 пака), `judge-profiles.json`, SQLite `data/lot.db` |
| Судья | OpenCodeGo (`gpt-6-luna`) + TMDb + mock |
| Деплой | systemd `lot.service`, Caddy, Cloudflare |

## Структура

```

src/render.ts      состояние → HTML (патчи по id)
src/store.ts       bun:sqlite: rooms, sessions, games; отложенная запись
src/ai.ts          OpenAI-совместимый клиент, три режима судьи, TMDb, mock
src/content.js     паки и профили судейства
public/            style.css + redesign.css + stages.css, experience.js, sound.js, sw.js, vendor/
tools/             verify, http-e2e, ui-e2e, balance-sim, shot, lib
test/sim-bun.mjs   боты по HTTP
deploy/            smoke.sh, vps/ (bootstrap, deploy, lot.service, Caddyfile)
data/              lot.db и images/ (в git не попадают)
screenshots/       локальные кадры (в git не попадают: bun run shots)
```

## Локально

```sh
bun install          # только dev-типы и tsc
bun run dev          # http://localhost:4173
LOT_MOCK=1 bun run dev   # судья без внешних вызовов
```

Секреты читаются из `~/.config/draft-party/opencode.env` (или `LOT_ENV`), на проде — из `EnvironmentFile` юнита:

```
OPENCODEGO_BASE_URL=https://opencode.ai/inference/openai/v1
OPENCODEGO_MODEL=gpt-6-luna
OPENCODEGO_API_KEY=...
TMDB_READ_ACCESS_TOKEN=...
LOT_OPS_TOKEN=...        # необязательный: детали /health
```

`LOT_IMAGE_ALLOW_LOCAL=1` разрешает http и локальные адреса при загрузке обложек — только для e2e, на проде не выставляется.

## CI

`.github/workflows/verify.yml` на каждый пуш и PR гоняет две задачи:

- **check** — `bun install --frozen-lockfile`, `bun check`, нормы оценивания, экономическая симуляция (4 320 партий) и HTTP-e2e (12 сценариев);
- **ui** — ставит Chromium для Playwright и прогоняет UI-e2e на двух браузерах, обновляя снимки.

Локально то же самое: `bun run verify`.

## Производительность транспорта

- Первое SSE-подключение ничего не отправляет, если HTML уже на актуальной версии комнаты (`/stream?v=N` против `room.version`). Раньше клиент получал повторный рендер на ~250 КБ.
- Дальше идут только точечные патчи: шапка и пульт лобби, а не весь каталог.
- Каталог (222 карточки, ~250 КБ) вынесен в отдельный ответ `/catalog?lang=ru&v=<версия>`: он неизменяем и кешируется браузером и Cloudflare на год, а страница комнаты весит ~15 КБ. Карточки подставляет `experience.js`, выделение пака — из `data-selected`; поиск и фильтры работают по уже вставленному DOM.
- Лобби входит только точечными патчами: приход второго игрока, присутствие и свои паки не пересылают каталог на 250 КБ — кадр выходит ~4 КБ (`#room-bar`, `#lobby-side`, `#invite-card`, `#custom-packs`).
- Статика отдаётся без `Set-Cookie` и с `?v=<версия сборки>`: `immutable` на год, поэтому Cloudflare её кеширует (`cf-cache-status: HIT`), а браузер не перепроверяет. Вендор версионирован именем файла. Байты файлов держатся в памяти процесса.
- Миниатюры пиков берут у TMDb `w92` вместо `w342` (26 px в отчёте), плашка лота — `w342`; прокси `/img/tmdb/<size>/<file>` кеширует размеры раздельно.
- Статика сжимается на origin в порядке **zstd → gzip**; `text/event-stream` не сжимается, чтобы не буферизовать поток. Brotli доступен только на edge Cloudflare и не используется, пока origin отдаёт сжатый ответ.

## Нормы оценивания

Единые шкалы лежат в `src/norms.ts` — из них собираются и промпты модели, и блок «Нормы оценки» в отчёте:

| Полоса | Партия | Сила персонажа | Спорт |
| --- | --- | --- | --- |
| 1–2 | мимо | обычный человек | любительский уровень |
| 3–4 | ниже нормы | уличный уровень | резерв / лига ниже топ |
| 5–6 | норма | городской / командный | крепкий профи топ-лиги |
| 7–8 | сильно | континентальный / армейский | звезда с наградами |
| 9–10 | выдающееся | планетарный и выше | доминация эпохи |

Правила: средняя по драфту ≈ 6, не больше одной десятки на драфт, при отсутствии данных — ровно 5 с пометкой, цена и ставки не влияют. Для TMDb — байесовское взвешивание `(V·R + 500·7.0) / (V + 500)` и порог 20 голосов, чтобы 30 оценок не обходили 20 000. Проверка: `bun run norms`.

## Как идёт партия

`lobby → toss → auction → judging → results`

- Хост выбирает пак и судью, монета решает, кто открывает торги.
- Ставка: `opening` (1–5) или `+$1` к текущей; перебитая ставка возвращается.
- Пас при чужой ставке отдаёт лот лидеру; два паса — лот пропущен.
- Пятый пик закрывает драфт; оставшиеся лоты уходят второму игроку бесплатно.
- Судья: `party` (Luna), `character-power` (только каноничная сила), `athlete-performance` (только статистика), `internet-ratings` (TMDb как есть).

## Инварианты

- Бюджет 20 монет: `остаток + потрачено = 20` в любой момент.
- Максимум 5 пиков на игрока, 10 лотов в партии.
- Если все пасуют, недостающие пики раздаются из пропущенных лотов — у обоих всегда ровно пять предметов.
- Загруженный пак проверяется на сервере: ≤64 КБ, 5–60 уникальных предметов, управляющие символы вырезаются; в общий каталог он не попадает.
- Обложка пака: хозяин стола вставляет ссылку (`/act/cover`), сервер скачивает картинку, проверяет магию байтов и перекодирует через `Bun.Image` в два webp — 96 px для плитки каталога и 192 px для пульта. Хранится в `data/images/<sha256>-96.webp|-192.webp`, метаданные — в таблице `images`, привязка «игрок → пак» — в `pack_covers`. Так можно поставить картинку на любую из 222 категорий (и на свой пак); у гостя она просто видна.
- Постер лота: у хозяина на плашке есть тихая кнопка ✦ — открывает тот же поиск, но по названию лота (запрос можно уточнить), либо поле для ссылки. Постер привязывается к игроку и паку, поэтому в следующих столах с этим паком предмет уже с картинкой; снимается там же.
- Картинки предметов: в JSON своего пака предмет можно задать объектом `{"name":"…","image":"https://…"}`. Пак ставится сразу, а картинки качаются в фоне по четыре за раз и падают в комнату патчами — постер появляется на плашке лота и миниатюрой в итогах. Размеры: 92 px для миниатюры и 342 px для плашки (2:3).
- Подбор обложки: кнопка «Найти картинку» ищет в Wikimedia Commons, при пустом ответе — в Openverse. Шесть кандидатов сразу скачиваются в наше хранилище (превью с чужого домена CSP не пустит), рядом с автором и лицензией; выбранный вариант несёт атрибуцию в форму. Запросы кешируются на 10 минут, пустой ответ не кешируется. Адреса API можно переопределить (`LOT_COMMONS_API`, `LOT_OPENVERSE_API`) — этим пользуется e2e.
- Подпись к чужой картинке («Фото: автор · лицензия») выводится под описанием лота и в диалоге обложки; она хранится в `images` вместе с исходной ссылкой.
- Ссылка проверяется на SSRF: только https, публичные адреса (DNS-резолв, приватные и служебные диапазоны закрыты), без логина в URL, до четырёх редиректов с повторной проверкой, таймаут 9 с, потолок 6 МБ по факту чтения. SVG не принимается, тип определяется по байтам, а не по заголовку источника. Лимит — 8 попыток залпом и одна в 3 с.
- Обложки приходят в каталог отдельным JSON-блоком `#pack-covers` и подставляются клиентом: сам каталог остаётся неизменяемым, поэтому кеш Cloudflare не ломается. Картинки отдаются с `/img/x/…` как `immutable` и без cookie.
- Свои паки остаются у игрока: до 12 штук за постоянным `lot_pid`, id считается от содержимого (повторная загрузка не плодит копий), пак переезжает в новый стол и ставится на стол одним кликом. Сам пак по-прежнему привязан к комнате и на других игроков не влияет.
- Повтор оценки ограничен: не больше 3 раз и не чаще раза в 8 секунд; смена судьи отменяет незавершённый запрос к модели.
- Действия валидируются на сервере: ход, бюджет, фаза, место.
- Частота запросов ограничена ведром токенов: `/act/*` — 60 в запасе и 8/с на сессию, создание стола — 20 и 1/6 с на адрес, вход по коду — 40 и 1/2 с, загрузка пака — 6 и 1/5 с. Сверх лимита — `429` с `Retry-After`.
- `/health` публично отдаёт только `ok` и `uptime`; счётчики комнат, базы и состояние судьи — по заголовку `x-lot-ops` с токеном `LOT_OPS_TOKEN`.
- `/robots.txt` и `/sitemap.xml` собираются от текущего origin; `/sw.js` отдаётся без кеша и с подставленной версией статики, поэтому новый деплой = новый кеш. Service worker кеширует только лендинг и статику: `/stream`, `/act/*`, `/img/` и `/api/` не кешируются никогда.
- Комнаты и сессии переживают рестарт; партии пишутся в `games`.

## Ограничения

- Datastar исполняет выражения через `new Function`, поэтому CSP содержит `'unsafe-eval'` (как в bunker9, где CSP нет вовсе). Остальные директивы строгие: `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`.
- TMDb-оценки кешируются в памяти процесса на 7 дней.
- Комнаты без активности живут 12 часов; пустые лобби убираются раньше.
